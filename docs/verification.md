## 標準プレビューへの依存

- `markdown.api.render` で標準の Markdown レンダラーを利用し、`markdown.markdownItPlugins` でセルと表の元テキストを付与する。
- 独自プレビューは、インストール済み拡張の `markdown.previewScripts` と `markdown.previewStyles` を収集する。Mermaid と数式は利用可能な拡張に依存する。
- 標準プレビューのデータ要素、内部スクリプト、更新・スクロールメッセージの形式を模倣している。これらは VS Code の内部実装に依存し、将来の変更で動かなくなる可能性がある。
- 本体スクリプトが描画しない場合は簡易更新を使う。元のセルの Markdown が取得できない場合は、書式を失う編集を避けて操作を停止する。行列操作は表示した表の内容と現在の文書が一致する場合に限り適用する。
- セル編集は編集開始時のセルの内容、履歴の復元は文書のバージョンと表全体を照合する。セルの内容が同じ別行に移動する競合など、すべての競合を検出できるわけではない。

## 実行方法

`npm test` は Node.js の単体テスト、`npm run test:integration` はインストール済み VS Code を使った Extension Host テストを実行する。`npm run package -- --out extension.vsix` の後に `npm run test:vsix -- extension.vsix` を実行すると、別の拡張フォルダーに VSIX をインストールして同じテストを行う。`npm run test:e2e` は開発版を独立した実 VS Code に読み込み、画面と一時ファイルの両方を検証する。失敗時は `test-results/` に画面画像とログを残す。Windows では標準のインストール先を使い、別の場所にある場合は `VSCODE_BIN` に `Code.exe` のパスを指定する。テストは独立したユーザーデータと拡張フォルダーを使う。

## 2026-11-01 英語対応の検証

Debian 13 / Node.js 24.19.0 / VS Code 1.144.0 / Xvfb で確認した。コマンド・設定説明は `package.nls.json` と `package.nls.ja.json`、ホストの通知とプレビューのメニューは `media/i18n.js` を使用する。VS Code の表示言語が日本語の場合は日本語、それ以外は英語にフォールバックする。

- 単体テスト12件が成功。日本語・英語・未対応言語のフォールバック、ブラウザー側での翻訳、表示言語に応じた編集停止メッセージを含む。
- 英語の Extension Host テスト8件が成功。
- VSIX を独立したプロファイルへインストールした状態で同じ8件が成功。翻訳リソースの同梱を確認した。
- 英語 UI の画面操作テスト5項目が成功。セル編集・Tab・自動保存、Undo/Redo、ソート・フィルタ、行列の追加・削除、外部編集との競合時の停止を確認した。

統合テストは `VSCODE_BIN` に VS Code の実行パスを指定し、Xvfb 下で `npm run test:integration` と `npm run test:vsix -- extension.vsix` を実行した。Linux の VSIX インストールには `bin/code`、テスト本体には Electron 実行ファイルを使うラッパーを利用した。コンテナー内では `--no-sandbox` を付与した。

画面テストは `npm run test:e2e` を使用する。`MDT_TEST_LOCALE` の既定は `en`。日本語を検証するときは `ja` を指定し、テストが作成する一時プロファイルに言語パックを導入する必要がある。言語パックがない状態では `--locale=ja` だけで日本語にならず、最初の日本語画面テストはコマンド検索でタイムアウトした。

日本語言語パックは公式 `microsoft/vscode-loc` のコミット `62d5443b567022539ba6e8565b0f43f5f6b3682b`（1.131.0）から検証用 VSIX を作成し、一時プロファイルへ導入して再試行した。ただし、この VS Code 1.144.0 では画面が英語のままで、日本語コマンド検索が再びタイムアウトした。日本語の実画面テストは未合格であり、日本語対応について今回確認できたのは単体テストの翻訳・言語判定まで。英語 UI の成功結果と区別する。
